# Движок: решение и план

Вопрос: переносить ли «Стальной Штурм» на другой движок (Unreal, Unity и т. д.) ради производительности и
графики. Условия: обязательно C++; сборка APK должна идти в этой облачной среде.

## Что есть в среде сборки (проверено)

| Ресурс | Есть | Нужно Unreal Engine 5 |
|---|---|---|
| Свободный диск | 18 ГБ | ~60 ГБ готовая сборка, 340+ ГБ сборка из исходников (версия 5.4) |
| Память | 15 ГБ | 32 ГБ и больше |
| Видеокарта | нет | нужна для редактора и запекания |
| Доступ к исходникам | только репозиторий игры | закрытый репозиторий Epic, привязка аккаунта |

## Варианты

| Движок | C++ | Собрать APK здесь | Графика на телефоне | Цена переноса |
|---|---|---|---|---|
| **Unreal Engine 5** | да | **нет** — не помещается, нет доступа к исходникам | лучшая «из коробки», но на телефонах урезанный рендер, тяжёлый APK | всё заново: ~30 тыс. строк, интерфейс, эффекты, импорт моделей |
| **Unity** | **нет** (C#; C++ только плагинами) | нужна лицензия и вход в аккаунт | хорошая | всё заново и не на C++ |
| O3DE | да | нет — сборка десятки ГБ | хорошая | всё заново |
| Свой движок (SDL / bgfx / Filament) | да | да | какую напишу сам | рендер, звук, интерфейс, импорт — с нуля; месяцы без новых возможностей игры |
| **Godot 4 + C++ (сейчас)** | да — бой, ИИ, пехота, авиация, генерация карт уже на C++ (≈12 тыс. строк) | да, работает | рендер Vulkan Mobile не включён — есть запас | ноль простоя |

## Решение

**Остаёмся на Godot 4 как на среде исполнения и доводим проект до «C++-игры на Godot».**

1. Unreal и Unity не проходят по вашим же условиям: Unreal здесь нельзя ни получить, ни собрать, Unity — не C++.
   Если Unreal нужен принципиально, сборка возможна только на вашем компьютере (Windows/Linux, 32+ ГБ памяти,
   100+ ГБ диска, аккаунт Epic); из этой среды я смогу лишь писать код вслепую, без сборки и проверки.
2. Узкое место игры — не марка движка. Симуляция уже на C++; картинку ограничивают рендер OpenGL ES
   (Compatibility) и ассеты. Оба ограничения снимаются без переписывания игры.
3. Перенос на любой другой движок — это месяцы, в которые игра не получает ничего нового, и потеря всего
   отлаженного: 3.0–3.7, вылеты на 3-м бою, оптимизация под Mali-G710.

## План (без простоя, каждый шаг — рабочий APK)

1. ~~**Рендер Vulkan Mobile**~~ — **отказались (4.2)**: экспериментальный APK на Vulkan больше не собирается,
   игра остаётся на OpenGL ES (Compatibility). Производительность берём оптимизацией: LOD растительности,
   разнесённые по шагам планы пехоты, позы бойцов в C++.
2. **Остаток кадрового GDScript — в C++**: ~~отрисовка пехоты~~ (позы и матрицы бойцов — в C++ с 4.2),
   самолёты (`infantry.gd`), частицы (`fx.gd`), разбор событий боя. Интерфейс и ангар остаются на GDScript — их перенос кадров не даёт.
3. **Графика ассетами**: текстуры земли и построек из Poly Haven / ambientCG (CC0) с картами нормалей, модели
   окружения вместо процедурных.
4. **Лётный режим** — на готовой основе (`air.inc`, `air_input`, `air_view`).

Источники цифр по Unreal: Arch Linux wiki (размер сборки 5.4), руководства по установке на Ubuntu; по
рендерам Godot — официальная документация «Overview of renderers».
